# step2.3 이미지 크기 개선

step2.2까지 APP 이미지는 1.68GB(내려받는 양 431MB)였다. 대부분이 바탕 이미지 `python:3.14`(Debian 전체 + 컴파일러 · 개발 도구)다. step2.3은 **무엇을 바탕으로, 무엇만 담나**를 바꾼다. 명령 순서 · 캐시 마운트(2.2)와 비root 실행(2.1)은 그대로다.

## 1. 바탕 이미지 후보

| 후보 | 기반 | 특징 | 결정 |
|---|---|---|---|
| `python:3.14` | Debian 전체 | gcc · 헤더 등 포함. 부품을 직접 컴파일해야 할 때 편하다 | step2.2까지 |
| `python:3.14-slim` | Debian 최소 | 컴파일러 없음. glibc | 후보 |
| `python:3.14-alpine` | Alpine (musl) | 가장 작다. 쓰는 부품 4개(fastapi · uvicorn · PyMySQL · cryptography)가 모두 musl용 완성본(wheel)을 제공해 컴파일이 필요 없다 | **선택** |
| distroless | 셸 없음 | 가장 줄일 수 있지만 셸 · 패키지 도구가 없어 수업 범위의 확인(`docker exec ... sh`)이 어렵다 | 미선택 |

alpine을 고를 때 확인한 것: 부품 설치에 컴파일이 필요 없을 것, `adduser`/`addgroup`(busybox) 문법이 다를 것, 건강 검사에 쓰는 python이 있을 것.

## 2. Dockerfile 변경

| 이미지 | 변경 | 이유 |
|---|---|---|
| APP | `ARG PYTHON_IMAGE=python:3.14-alpine`, `FROM ... AS build` / `FROM ... AS runtime` | 설치하는 곳과 실행하는 곳을 나눈다 (멀티스테이지) |
| APP | build: `python -m venv --without-pip /opt/venv` → `pip --python /opt/venv/bin/python install` (캐시 마운트 유지) | 부품을 한 폴더에 모아 runtime으로 `COPY --from=build /opt/venv` 만 옮긴다. 가상환경 안에 pip(약 13MB)를 넣지 않는다 |
| APP | runtime: `addgroup -S -g 10001 app && adduser -S -D -H -u 10001 -G app ...` | alpine(busybox) 방식. UID 10001 · `USER 10001` 은 그대로 |
| APP · Web | `.dockerignore` 넓힘: `Dockerfile` · `.dockerignore` · `__pycache__` · `*.pyc` · `*.md` · `docs` · `tests` · `*.log` · `.venv` 등 (Web은 1단계용 `nginx.conf` 도) | 이미지에 필요한 것만: APP은 `app.py` · `requirements.txt`, Web은 템플릿 · `html/`. Dockerfile만 고쳐도 소스 복사 층이 다시 만들어지던 것도 사라진다 |
| Web | `nginxinc/nginx-unprivileged:1.30` → `1.30-alpine-slim`, 건강 검사 `curl` → `wget` | alpine-slim에는 curl이 없다. envsubst(템플릿)는 있다. UID 101 · 8080 그대로 |
| 스크립트 | 기본 태그 `step2.3`, `docker/measure-size.sh` 추가 | A(step2.2) → B(slim) → C(alpine) → D(step2.3) 를 한 번에 하나씩 바꿔 크기를 잰다 |
