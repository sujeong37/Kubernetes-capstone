# step3.4 DB 준비 — 클러스터 안 MySQL + PVC

평가 기준 「데이터와 설정」(DB 데이터를 볼륨에 저장해 DB Pod를 교체해도 유지, 비밀번호는 Secret)과
「노출」의 뒷부분(DB는 클러스터 안에서만 접근)을 채운다. 수업 Kubernetes Core 09장(스토리지: local-path, PVC,
Gallery 영구 스토리지)과 10장(Gallery 설정 분리: Secret · secretKeyRef)을 Bus에 적용한다.

| 2.4 compose | 3.4 Kubernetes (`k8s/step3/`) |
|---|---|
| `image: mysql:8.4` + `restart` | Deployment `db` (replicas 1, **Recreate**) |
| 볼륨 `bus-db-data:/var/lib/mysql` | PVC `db-data` (1Gi, RWO, 기본 StorageClass local-path) |
| `./app/db:/docker-entrypoint-initdb.d:ro` | ConfigMap `db-init` (init.sql · grants.sql) |
| `MYSQL_*_PASSWORD: ${...:?}` | Secret `bus-db` (root-password · username · password), `create-secrets.sh`로 파일 없이 생성 |
| healthcheck `mysqladmin ping` | readinessProbe 같은 명령, livenessProbe tcp 3306 |
| 서비스 이름 `db`, 포트 공개 없음 | Service `db` (ClusterIP) — NodePort 없음 |

## 순서

1. local-path-provisioner v0.0.37 설치 + 기본 StorageClass 지정 (수업 09-02와 같음)
2. `kubectl apply -f namespace.yaml` → `bash create-secrets.sh` (비밀번호 무작위 생성 → `~/.bus-step3/bus.env` 600, TAGO 키 입력)
3. PVC → Pending (WaitForFirstConsumer) 확인
4. ConfigMap · Deployment · Service 적용 → PVC Bound, PV nodeAffinity
5. 초기화 확인: `favorites` 표, bus 권한 4개, CREATE 거부
6. 데이터 유지: 등록 → DB Pod 삭제 → 같은 노드에 새 Pod → 같은 행
7. 노드 고정 한계: DB 노드 cordon → Pod 삭제 → Pending(FailedScheduling: PV node affinity) → uncordon
8. 클러스터 안에서만: Pod에서 `nc db 3306` 성공, 내 PC → 노드 공인 IP:3306 실패, Service TYPE ClusterIP

## 비밀값

- Secret 매니페스트는 Git에 없다. `kubectl create secret ... --dry-run=client -o yaml | kubectl apply --server-side -f -`
- DB 접속 확인은 컨테이너의 환경 변수(`$MYSQL_PASSWORD`)를 그대로 써서 비밀번호를 입력 · 출력하지 않는다.
