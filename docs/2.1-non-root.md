# step2.1 root가 아닌 사용자로 실행

step2.0의 이미지 2개는 컨테이너 안에서 root(관리자, UID 0)로 실행됐다. step2.1은 **누구로 실행하나만** 바꾼다. 명령 순서(→ 2.2)와 바탕 이미지 크기(→ 2.3)는 그대로 둔다.

| | root로 실행 (step2) | 일반 사용자로 실행 (step2.1) |
|---|---|---|
| 프로그램이 뚫리면 | 컨테이너 안 모든 파일을 고치고, 부품을 바꿔 끼울 수 있다 | 고칠 수 있는 파일이 없다 (읽기 · 실행만) |
| Kubernetes (3 · 4단계) | `runAsNonRoot: true` 정책이 있으면 실행 거부 | 통과 |
| 1024 아래 포트(80 등) | 열 수 있다 | Kubernetes에서는 열 수 없다 → web은 8080 |

## 1. Dockerfile 변경

| 이미지 | 변경 | 이유 |
|---|---|---|
| APP | `RUN useradd --uid 10001 --user-group --no-create-home --shell /usr/sbin/nologin app` (pip install 뒤) | 실행 전용 계정. UID 10001은 바탕 이미지의 사용자(0~999 등)와 겹치지 않게 큰 수 |
| APP | `USER 10001` (HEALTHCHECK · CMD 앞) | 이름이 아니라 **숫자**로 적는다. Kubernetes는 이미지 안의 사용자 목록을 읽지 않아서, 이름이면 root인지 판단하지 못해 `runAsNonRoot` 에서 거부한다 |
| APP | 앱 파일 · 설치한 부품은 root 소유 그대로 | COPY · pip install 은 root로 했으므로 실행 사용자는 읽고 실행만, 고치지 못한다 |
| Web | `FROM nginx:1.30` → `FROM nginxinc/nginx-unprivileged:1.30` | 공식 nginx는 마스터 프로세스가 root로 떠야 한다(pid 파일 · 임시 폴더 · 80번). 같은 Nginx 1.30을 처음부터 UID 101로 돌도록 바꿔 둔 비root판(nginxinc 제공) |
| Web | `listen 80` → `listen 8080` (템플릿), `EXPOSE 8080`, HEALTHCHECK 8080, `USER 101` | 1024 아래 포트는 Kubernetes에서 root만 열 수 있다 |
| 스크립트 | `up.sh` 의 web 게시 `127.0.0.1:8080:80` → `127.0.0.1:8080:8080` (step2 태그면 자동으로 80) | 브라우저 주소는 그대로 localhost:8080 |
| 스크립트 | build · up · push 기본 태그 `step2` → `step2.1` | 현재 단계. 이전 이미지는 `IMAGE_TAG=step2` |

사용자 만들기를 pip install **뒤**에 둔 것은 step2.1이 실행 사용자만 바꾸기 때문이다. 순서 · 캐시는 step2.2에서 정리한다.

## 2. 1024 아래 포트 — Docker와 Kubernetes의 차이

| 실행 환경 | `ip_unprivileged_port_start` | UID 10001이 80번을 열면 |
|---|---|---|
| Docker Engine 20.10 이상 (컨테이너 기본) | 0 | **열린다** (`Uvicorn running on http://0.0.0.0:80`) |
| Kubernetes(containerd) Pod 기본 · 일반 리눅스 | 1024 | `[Errno 13] ... permission denied` |

Docker는 컨테이너 네트워크 안에서 이 값을 0으로 낮춰 두기 때문에 Docker에서만 보면 80번도 된다. 3 · 4단계 Kubernetes에서는 기본값 1024가 적용되므로, 어디서든 같은 이미지가 돌게 web은 8080으로 정했다. `docker run --sysctl net.ipv4.ip_unprivileged_port_start=1024` 로 Kubernetes와 같은 조건을 만들어 확인한다.

## 3. 확인한 것 (Claude 작업 환경, 같은 이름의 대체 바탕 이미지)

| 확인 | step2 | step2.1 |
|---|---|---|
| `Config.User` | (없음) | APP `10001`, Web `101` |
| `id` | `uid=0(root)` | APP `uid=10001(app)`, Web `uid=101(nginx)` |
| 크기 (APP) | 480MB / 115MB | 480MB / 115MB (사용자 층 수 KB) |
| `touch /app/hack.txt` | 성공 | `Permission denied` |
| Web 화면 폴더에 쓰기 | — | `Permission denied` |
| `up.sh` → `test.sh` | 9 / 9 | 9 / 9 |
| 80번 (Docker 기본) | — | 열림 |
| 80번 (`--sysctl ...=1024`) | — | `permission denied` |

대체 바탕 이미지는 공식 nginx를 고쳐 만든 것이라 ExposedPorts에 80이 남았다. 실제 `nginxinc/nginx-unprivileged` 는 8080만 있다. 실제 값은 Runbook 수행 결과로 기록한다.
