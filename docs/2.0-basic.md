# step2.0 기본 형태 — 이미지 빌드 · 컨테이너 실행 · 배포

1단계(WSL에 직접 설치)에서 돌린 앱을 **이미지 2개 + 공식 DB 이미지**로 바꿔 컨테이너로 실행하고, 같은 테스트 시나리오(T1~T9)를 통과한 뒤 레지스트리(Docker Hub)에 linux/amd64 로 올린다.

이 단계의 Dockerfile은 **일부러 가장 기본 형태**다. 다음 단계에서 하나씩 고치고 전후를 숫자로 비교한다.

| 지금 (step2.0) | 고치는 단계 |
|---|---|
| 컨테이너 안에서 root로 실행된다 (USER 없음) | step2.1 |
| 소스를 먼저 복사하고 부품을 설치해서, 코드 한 줄만 고쳐도 부품을 처음부터 다시 설치한다 | step2.2 |
| 바탕 이미지가 공식 기본판(Debian 전체, 컴파일러 등 포함)이다 | step2.3 |
| .dockerignore는 꼭 빼야 할 것만 뺀다 (Dockerfile · 문서는 이미지에 들어감) | step2.3 |
| 컨테이너를 docker run으로 하나씩 띄운다 | step2.4 (Compose) |

## 1. 이미지와 컨테이너

| 컨테이너 | 이미지 | 내 컴퓨터에서 접속 | 역할 |
|---|---|---|---|
| db | `mysql:8.4` (공식) | — (열지 않음) | 즐겨찾기 저장. 데이터는 볼륨 `bus-db-data` |
| app | `bus-app:step2` (우리 코드) | `127.0.0.1:8000` | FastAPI. 정류장 검색 · 도착 정보 · 즐겨찾기 |
| web | `bus-web:step2` (우리 코드) | `127.0.0.1:8080` | Nginx. 화면 + `/api` 를 app으로 넘김 |

3 · 4단계(Kubernetes · EKS)에 올리는 이미지는 `bus-app` · `bus-web` 2개다. DB는 3단계에서 클러스터 안 MySQL, 4단계에서도 같은 공식 이미지를 쓴다.

## 2. Dockerfile (step2.0)

| 명령 | APP (`app/was/Dockerfile`) | Web (`app/web/Dockerfile`) |
|---|---|---|
| FROM | `python:3.14` (공식 기본판) | `nginx:1.30` (공식 기본판) |
| WORKDIR | `/app` | — |
| COPY | 소스 폴더 전체 `COPY . /app/` | 설정 템플릿 → `/etc/nginx/templates/`, 화면 → `/usr/share/nginx/html/` |
| RUN | `pip install -r requirements.txt` | — |
| ENV | `PYTHONUNBUFFERED=1` | `APP_ADDR=app:8000` (템플릿의 `${APP_ADDR}` 를 시작할 때 채움) |
| EXPOSE | 8000 | 80 |
| HEALTHCHECK | 10초마다 python으로 `/api/healthz` | 10초마다 `curl -fs http://127.0.0.1/` |
| CMD | `["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]` | 바탕 이미지의 것 (`nginx -g "daemon off;"`) |

설정 · 비밀 값의 위치:

| 값 | 위치 | 이유 |
|---|---|---|
| `DB_HOST=db` · `DB_PORT` · `DB_NAME` · `DB_USER` · `CITY_CODE` | `docker/env.docker` (`--env-file`) | 비밀이 아닌 공통 설정. 주소는 컨테이너 이름 |
| `DB_PASSWORD` · `DB_ROOT_PASSWORD` · `TAGO_SERVICE_KEY` | `up.sh` 가 화면에 보이지 않게 입력받아 `-e 이름`(값 없이)으로 전달 | 이미지 · 저장소 · 명령 기록에 남기지 않는다 |

## 3. .dockerignore (step2.0 — 꼭 빼야 할 것만)

| 뺀 것 | 이유 |
|---|---|
| `*.pem` `*.key` `*.crt` `.env` `.env.*` | 비밀 정보. 이미지에 들어가 레지스트리에 올라가면 누구나 꺼내 볼 수 있다 |
| `.git` | 레포 기록. 필요 없고 크다 |
| `.venv` | 1단계에서 만든 가상환경. 이미지 안에서 새로 설치하므로 섞이면 안 된다 |

## 4. 스크립트 (`docker/`)

| 파일 | 하는 일 |
|---|---|
| `build.sh` | 이미지 2개 만들기 (`IMAGE_TAG`, 기본 `step2`) |
| `up.sh` | 네트워크 `bus-net` · 볼륨 → db(healthy 대기) → app(healthy 대기) → web. `IMAGE_PREFIX=계정/` 이면 레지스트리 이미지 |
| `down.sh` | 컨테이너 3개 삭제 (네트워크 · 볼륨 유지) |
| `test.sh` | 시나리오 T1~T9. T7 뒤에 down → up 으로 모두 다시 띄우고 T8(데이터 유지) 확인 |
| `push.sh` | `docker buildx build --platform linux/amd64` 로 만들어 올림. 태그 `step2` + `step2-<커밋>` (step2.1부터 기본 태그는 현재 단계) |
| `env.docker` | 컨테이너 공통 설정 (비밀 아님) |

## 5. 확인한 것 (Claude 작업 환경, 같은 이름의 대체 바탕 이미지)

| 확인 | 결과 |
|---|---|
| `build.sh` | 이미지 2개, 빌드 컨텍스트 APP 약 10kB(.venv 제외됨) |
| 가짜 `fake-secret.pem` 을 만들고 빌드 | 소스 폴더에는 있고 이미지 `/app` 에는 없음. `Dockerfile` · `.dockerignore` 는 들어 있음 (step2.3) |
| 실행 사용자 | root |
| `up.sh` | db → app → web 모두 `(healthy)`, 약 30초 |
| `test.sh` | 통과 9 / 9 (T8: 컨테이너 3개를 지우고 다시 띄워도 즐겨찾기 유지) |
| 이미지에 비밀번호 | `inspect` · `history` 에 0건 |
| db 정지 | `/api/favorites` 500, `/api/healthz` 200 (app 로그 `Can't connect to MySQL server on 'db'`), db 다시 켜면 200 |
| `push.sh` | 작업 환경은 Docker Hub · registry 이미지를 받을 수 없어 실행하지 못함 → Runbook 수행 결과로 기록 |

실제 크기 · 시간은 Runbook 수행 결과로 기록한다.
