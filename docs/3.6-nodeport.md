# step3.6 노출 — NodePort

평가 기준: 「클러스터 밖에서 APP 에 접속해 테스트 시나리오를 통과했다. DB 는 클러스터 안에서만 접근된다.」
수업 Kubernetes Core 06장(Service) NodePort 를 Bus 에 적용한다.

| Service | 3.5 | 3.6 | 밖(내 PC)에서 |
|---|---|---|---|
| web | ClusterIP | **NodePort 30080** | `http://<노드 공인 IP>:30080` — 세 노드 아무 곳이나 |
| app | ClusterIP | ClusterIP | 안 닿음 (web 의 Nginx 가 /api 를 넘김) |
| db | ClusterIP | ClusterIP | 안 닿음 |

## 왜 NodePort

- kubeadm 클러스터에는 클라우드 LoadBalancer 컨트롤러가 없다 → `type: LoadBalancer` 는 EXTERNAL-IP 가 `<pending>` 에 머문다.
- 보안 그룹은 3.0 부터 내 공인 IP 에만 22 · 30000-32767 을 열었다. NodePort 는 추가 설정 없이 그 범위를 쓴다.
- 번호를 30080 으로 고정해 Runbook · 테스트 주소가 바뀌지 않게 한다.
- 한계: 노드 공인 IP 가 EC2 를 켤 때마다 바뀌고, 노드 하나를 주소로 쓰면 그 노드가 죽을 때 끊긴다 → 3.8 Gateway · 4단계 ALB 로 해결.

## 확인 (Runbook)

1. `git diff` — 바뀐 것은 type · nodePort 두 줄
2. svc web `NodePort 8080:30080/TCP`, Endpoints = web Pod 2개
3. kube-proxy 가 모든 노드에 만든 규칙 (iptables KUBE-NODEPORTS)
4. 내 PC → cp · worker1 · worker2 :30080 모두 200 (cp 에는 web Pod 가 없다)
5. 브라우저로 화면 사용
6. 내 PC 에서 `tests/scenario.sh` — T7 뒤 멈춘 사이 app · db Pod 를 지우고 → T8 데이터 유지 · 9/9
7. 내 PC → :8000 · :3306 연결 실패, svc 목록에서 NodePort 는 web 하나
