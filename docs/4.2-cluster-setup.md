# step4.2 클러스터 기본 설정 (EKS)

| 실행 (WSL) | 하는 일 |
|---|---|
| `bash infra/step4/eks/setup-cluster.sh` | ① Gateway API 켜기(EKS 관리형 CRD) ② `kubectl apply -k k8s/eks-cluster` ③ namespace bus + Secret 2개 ④ 상태 |
| `bash infra/step4/eks/cluster-test.sh` | 시험 namespace 에서 A. EBS(WaitForFirstConsumer → Bound, gp3 · 암호화, 지우면 EBS 도 삭제) B. NetworkPolicy(통과 → 기본 거부 → 필요한 길만) 후 지움 |

## k8s/eks-cluster (클러스터 단위 — 앱 overlay 와 분리)

| 파일 | 내용 | 3단계에서는 |
|---|---|---|
| `storageclass.yaml` | `ebs` (기본) · `ebs.csi.eks.amazonaws.com` · gp3 · 암호화 · WaitForFirstConsumer · Delete | local-path 설치 (3.4) — 노드 폴더라 노드가 바뀌면 데이터가 따라가지 못했다 |
| `gatewayclass.yaml` | `eks-alb` → `eks.amazonaws.com/gateway-alb` (Auto Mode 내장 컨트롤러) | Envoy Gateway 설치 + GatewayClass envoy (3.8) |
| `vpc-cni-network-policy.yaml` | ConfigMap `amazon-vpc-cni` `enable-network-policy-controller: "true"` | Calico 가 처음부터 지켰다 (3.11) |

EKS Auto Mode 는 StorageClass 를 만들어 두지 않고, NetworkPolicy 는 켜기 전까지 지키지 않으며, Gateway API 는 클러스터 설정(`kubernetesNetworkConfig.elasticLoadBalancing.gatewayApi`)을 켜야 CRD 가 생긴다 (2026-10 기능 — 오래된 aws CLI 는 `install-aws-cli.sh --update`).

## Secret
`ENV_FILE=~/.bus-step4/bus.env` (WSL, 600) 로 `k8s/step3/create-secrets.sh` 를 그대로 쓴다. EKS 의 DB 는 새 디스크라 비밀번호도 새로 만든다. TAGO 키는 `read -s` 로 입력 — 화면 · Git 에 남지 않고 이름 · 길이만 출력.
