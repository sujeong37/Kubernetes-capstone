# step3.5 원시 매니페스트로 배포 — app · web

수업 Kubernetes Core 08장 05(Gallery: app Deployment + init container + Probe) · 10장 05(설정 분리)를 Bus 앱에 맞춘다.
Helm · Kustomize 없이 YAML 과 `kubectl apply` 만 쓴다. 이미지는 2.3 에서 Docker Hub 에 올린 `sujeong79/bus-app:step2.3` · `sujeong79/bus-web:step2.3` 그대로.

## compose (2.4) → Kubernetes (3.5)

| compose.yaml | k8s/step3 | 이유 |
|---|---|---|
| `env_file: docker/env.docker` | ConfigMap `bus-app-config` (DB_HOST=db · DB_PORT · DB_NAME · CITY_CODE) + `envFrom` | 비밀 아닌 설정을 이미지 밖에. 같은 이미지를 다른 환경에 |
| `DB_PASSWORD` · `TAGO_SERVICE_KEY` 셸 변수 | `secretKeyRef` → Secret `bus-db` · `bus-tago` (3.4 에서 생성, Git 밖) | 비밀값이 매니페스트 · 이미지 · Git 에 없다. TAGO 는 `optional: true` (없으면 가짜 데이터) |
| `depends_on: db: service_healthy` | init container `wait-db` (busybox `nc -z db 3306` 반복) | 앱 컨테이너는 DB 포트가 열린 뒤에 시작 |
| `healthcheck` (이미지) | readinessProbe · livenessProbe `GET /api/healthz` · web `GET /` | Ready 인 Pod 만 Service Endpoints 에 들어간다. 멈추면 kubelet 이 재시작 |
| 컨테이너 1개 | `replicas: 2` + topologySpreadConstraints(hostname) | worker1 · worker2 에 하나씩 |
| (없음) | `RollingUpdate maxUnavailable 0 · maxSurge 1` | 업데이트 중에도 준비된 Pod 2개 유지 (3.7) |
| `web depends_on app service_healthy` | 없음 | Nginx 는 시작할 때 `app` 주소를 고정한다. compose 에서는 컨테이너 IP 라 바뀌면 502, k8s 에서는 Service ClusterIP 라 Pod 가 바뀌어도 그대로 |
| `ports: 127.0.0.1:8080:8080` | Service `web` ClusterIP (3.6 에서 NodePort) | 3.5 는 클러스터 안에서만 확인 |
| `USER 10001` · `USER 101` | `runAsNonRoot` · `allowPrivilegeEscalation: false` · `drop ALL` · seccomp RuntimeDefault | 이미지의 비root 를 kubelet 이 강제로 확인 |

## 자원 요청

3.3 에서 측정한 worker 남은 CPU: worker1 1.65 · worker2 1.75 vCPU.

| 컨테이너 | requests cpu / memory | limits memory |
|---|---|---|
| app ×2 | 50m / 64Mi | 256Mi |
| web ×2 | 20m / 32Mi | 128Mi |
| wait-db (init) | 10m / 16Mi | 32Mi |
| db ×1 (3.4) | 100m / 384Mi | 768Mi |

CPU limit 은 두지 않는다 (throttling 으로 응답이 느려지는 것을 피함). 메모리 limit 은 둔다 (새는 경우 그 Pod 만 OOMKilled).

## 확인 순서 (Runbook)

1. `git pull` → 매니페스트 읽기
2. ConfigMap · Secret 참조 확인
3. DB 를 0 으로 줄인 채 app 배포 → `Init:0/1` + "waiting for db:3306" → DB 1 로 → app Ready (시간 측정)
4. 배치 · Endpoints (Ready 인 Pod IP 만)
5. web 배포 (app 을 기다리지 않는 이유)
6. 클러스터 안 경로: 임시 Pod 에서 `wget web:8080/api/healthz`
7. cp 에서 `kubectl port-forward svc/web 8080:8080` + `WAIT=0 bash tests/scenario.sh http://localhost:8080` → 9 / 9
8. 비밀값이 어디에 보이는지 (describe 에는 Secret 이름 · 키만)
9. 노드별 requests 합계
