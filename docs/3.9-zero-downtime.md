# step3.9 무중단 롤링 — preStop

3.7 에서 롤링 업데이트 중 요청 215개 중 2개가 502 였다 (옛 Pod 가 내려갈 때마다 1건).

## 원인 — Pod 종료는 두 갈래로 동시에 진행된다

| 갈래 | 하는 일 |
|---|---|
| ① kubelet | 컨테이너에 SIGTERM → uvicorn · Nginx 가 곧바로 종료 |
| ② EndpointSlice 컨트롤러 → 각 노드 kube-proxy · Envoy | 이 Pod 를 서비스 목록에서 빼고 규칙을 다시 씀 (수백 ms ~ 수 초) |

①이 ②보다 빠르면, 목록에는 아직 있지만 프로세스는 없는 Pod 로 요청이 가서 연결 거부 → 앞단(Nginx)이 502.

## 해결 — preStop sleep 5

`lifecycle.preStop.sleep.seconds: 5` : kubelet 이 SIGTERM 을 보내기 전에 5초 기다린다.
그동안 ②가 끝나 새 요청이 더 오지 않고, 이미 받은 요청은 마저 처리한 뒤 프로세스가 멈춘다.
`terminationGracePeriodSeconds: 30` (기본값) 안에 preStop 5초 + 앱 정리가 들어간다.
sleep 액션은 Kubernetes 내장 기능이라 이미지에 sleep 명령이 없어도 된다.

## 확인 (Runbook)

같은 `kubectl rollout restart` 를 적용 전 · 후로 두 번씩, 그동안 내 PC 에서 0.2초마다 요청 → 실패 수 비교.
