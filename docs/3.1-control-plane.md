# step3.1 Control Plane 구성

수업 Kubernetes Core 02장 02(kubeadm 초기화 절차) · 03(PKI와 kubeconfig) · 04(Control Plane 기동과 첫 접속)를 cp 노드에서 그대로 따른다. 설정 파일은 수업 `02/03/kubeadm-config.yaml` 을 그대로 쓴다 (이 레포에 복사하지 않음, 내 PC `~\k8s-core` 에서 cp 노드의 작업 폴더 `~/k8s-bus` 로 scp).

| 필드 | 값 | 이유 |
|---|---|---|
| advertiseAddress | 192.168.56.10 | apiserver 접속 주소 · 인증서 SAN |
| kubernetesVersion | v1.36.5 | 노드 패키지(3.0)와 같은 버전 고정 |
| podSubnet · serviceSubnet | 10.244.0.0/16 · 10.96.0.0/12 | VPC 192.168.0.0/16 과 겹치지 않게, Calico(3.3)와 같은 Pod 대역 |
| serverTLSBootstrap | true | kubelet 서빙 인증서를 클러스터 CA에서 받음 → CSR 승인(3.2) |

## 순서

1. `kubeadm init --help` 단계 목록, `kubeadm config print init-defaults`
2. `kubeadm config validate`
3. `kubeadm init phase certs all` → apiserver 인증서 SAN · `openssl verify -verify_ip` (사설 IP OK / 공인 IP mismatch), etcd CA 분리
4. `kubeadm init phase kubeconfig all` → admin(kubeadm:cluster-admins) vs super-admin(system:masters) vs kubelet(system:nodes), `certs check-expiration`
5. 생성물 삭제(시작 상태 복원)
6. `kubeadm init --config kubeadm-config.yaml` — 출력 단계별 해석. join 명령은 비밀값이라 레포 · Notion에 두지 않는다
7. kubelet activating → active, `crictl ps` static Pod 4개, manifest 치우기 → 정지 · 되돌리기 → 새 컨테이너
8. `~/.kube/config` = admin.conf, 노드 NotReady(cni plugin not initialized) · taint 2개 · CoreDNS Pending, mirror Pod 삭제해도 static Pod 그대로, CSR(kubelet-serving Pending), ConfigMap kubeadm-config · kubelet-config
9. 스냅샷 대신 stop/start-cluster.ps1 후 같은 상태(RESTARTS 1)

## 클라우드 VM에서 다른 점

- SAN 실패 예시: 수업은 NAT 주소 10.0.2.15, EC2는 NAT 주소가 없어 cp 공인 IP로 확인한다 → 공인 IP로 apiserver에 붙지 않고 cp에 SSH로 들어가 kubectl을 쓴다 (보안 그룹도 6443을 밖에 열지 않음).
- 스냅샷(ch02-done) 대신 정지 · 기동.
