# step2.2 빌드 속도 개선

step2.1까지의 APP Dockerfile은 소스 전체를 먼저 복사(`COPY . /app/`)하고 부품을 설치했다. 그래서 코드 한 줄만 고쳐도 부품 설치(`pip install`)부터 다시 실행됐다. step2.2는 **명령 순서**와 **부품 내려받기 캐시**만 바꾼다. 바탕 이미지(→ 2.3)와 실행 사용자(2.1)는 그대로다.

## 1. 빌드 캐시가 동작하는 방식

Docker는 Dockerfile을 위에서부터 한 줄씩 보며 "지난번과 같은 명령, 같은 입력인가"를 확인한다. 같으면 지난번 결과를 그대로 쓰고(`CACHED`), **처음 달라진 줄부터 아래는 전부 다시 만든다.**

| 명령 | "같은가"를 판단하는 기준 |
|---|---|
| `RUN` · `ENV` · `EXPOSE` 등 | 명령 글자 그대로 |
| `COPY` | 복사하는 파일들의 내용 |

`COPY . /app/` 은 소스 폴더 전체가 입력이라 `app.py` 한 글자만 바뀌어도 달라지고, 그 아래 `pip install` 도 다시 실행된다.

## 2. Dockerfile 변경

| 이미지 | 변경 | 이유 |
|---|---|---|
| APP | `COPY requirements.txt /app/` → `RUN pip install` → … → `COPY . /app/` (맨 아래) | 부품 목록이 그대로면 설치 층은 `CACHED`. 소스를 고치면 맨 아래 복사만 다시 |
| APP | `ENV` · `WORKDIR` · `useradd` · `EXPOSE` · `HEALTHCHECK` 를 소스 복사 위로 | 소스와 상관없는 줄을 위에 모아 둔다 |
| APP | `RUN --mount=type=cache,target=/root/.cache/pip pip install ...` | 부품 목록이 바뀌어 설치를 다시 해도, 이미 받은 부품 파일은 Docker 쪽 보관함에서 꺼내 쓴다. 보관함은 이미지 밖이라 이미지에 들어가지 않는다 |
| APP | `ENV PIP_DISABLE_PIP_VERSION_CHECK=1` | 빌드 때 pip 새 버전 확인(인터넷 요청)을 하지 않는다 |
| Web | `ENV` · `EXPOSE` · `HEALTHCHECK` 위로, 화면 파일 `COPY html/` 맨 아래 | 같은 원칙. Web은 설치 단계가 없어 시간 차이는 작다 |
| 스크립트 | build · up · push 기본 태그 `step2.2`, `docker/measure-build.sh` 추가 | 4가지 경우 (a)~(d)를 같은 방식으로 잰다 |

## 3. 측정 (Claude 작업 환경, 대체 바탕 이미지 — 실제 값은 Runbook)

`bash docker/measure-build.sh <Dockerfile> <이름>` — (a) 빌드 캐시를 지운 뒤 처음, (b) 바로 다시, (c) `app.py` 끝에 주석 한 줄, (d) `requirements.txt` 끝에 주석 한 줄(부품은 그대로, 파일만 달라짐).

| 경우 | step2.1 | step2.2 |
|---|---|---|
| (a) 처음 빌드 | 13.7초 · 받은 부품 32 | 9.7초 · 32 |
| (b) 바뀐 것 없음 | 0.3초 · CACHED 4/5 | 0.3초 · CACHED 5/6 |
| (c) 소스 한 줄 | **8.6초** · CACHED 1/5 · 받은 부품 32 | **0.4초** · CACHED 4/6 · 0 |
| (d) 부품 목록 파일 | 12.3초 · CACHED 1/5 · 32 | 6.8초 · CACHED 2/6 · **0** (`Using cached`) |
| 이미지 크기 | 480MB / 115MB | 457MB / 104MB |
| 시나리오 | 9 / 9 | 9 / 9 |

| 개선된 것 | 이유 |
|---|---|
| (c) 소스 수정 후 재빌드 | 설치 층이 `CACHED`, 소스 복사(수십 KB)만 다시 |
| (d) 부품 목록 변경 | 설치는 다시 하지만 내려받기가 0 (캐시 마운트) |
| 이미지 크기 약 11MB 감소 | step2.1은 pip가 받은 파일(`/root/.cache/pip`, 12MB)이 설치 층에 남았다. 캐시 마운트는 이미지 밖이다 |

| 개선되지 않은 것 | 이유 · 다음 |
|---|---|
| (a) 처음 빌드 | 받을 것이 없는 상태라 같다. 바탕 이미지 크기가 대부분 → step2.3 |
| 이미지 크기 1.7GB(실제 python:3.14) | 바탕 이미지가 Debian 전체 → step2.3 |
| `.dockerignore` | 아직 최소. `Dockerfile` · `__pycache__` 등이 소스 복사에 들어간다 → step2.3 |
