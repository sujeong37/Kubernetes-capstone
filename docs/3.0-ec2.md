# step3.0 클라우드 VM 준비 (EC2 3대)

Kubernetes를 직접 설치할 빈 서버 3대와 네트워크를 AWS에 만든다. 이 단계에서는 Kubernetes를 설치하지 않고, 만들고 · 접속하고 · 서로 통신되는지만 확인한다. 구성은 수업 Kubernetes Core 01-04 [부록] 클라우드 VM 실습 환경과 같게 맞췄다 (노드 이름 · 사설 IP 고정 → 이후 수업 명령 · 출력을 그대로 쓴다).

## 1. 만드는 자원 (리전 ap-northeast-2)

| 자원 | 이름 | 내용 |
|---|---|---|
| VPC · 서브넷 | bus-step3-vpc · bus-step3-subnet-public-a | 192.168.0.0/16, 노드 대역 192.168.56.0/24 (ap-northeast-2a) |
| 인터넷 게이트웨이 · 라우팅 테이블 | bus-step3-igw · bus-step3-rtb-public | 0.0.0.0/0 → IGW |
| 보안 그룹 | bus-step3-sg-node | 노드끼리 모든 프로토콜, 내 공인 IP/32 에서만 22 · 30000-32767 |
| 키 페어 | key-bus-step3 (ed25519) | 개인 키 `~/.bus-step3/key-bus-step3.pem` (600, 레포 밖) |
| EC2 3대 | bus-step3-instance-{cp,worker1,worker2} | Rocky Linux 9 공식 AMI, t3.medium, 30GB gp3, 사설 IP .10 · .11 · .12, 호스트 이름 = 노드 이름 |

모든 자원에 태그 `Name` · `Organization=bus` · `Project=step3`. 정지 · 기동 · 삭제 스크립트는 두 태그로 자원을 찾는다.

## 2. 수업 스크립트에서 바꾼 것

| 바꾼 것 | 이유 |
|---|---|
| IMDSv2 만(`HttpTokens=required`) · 홉 제한 1, IAM 역할 없음 | Pod가 노드의 메타데이터 · 자격 증명을 가져가지 못하게 |
| 디스크 `DeleteOnTermination=true` | 삭제 후 EBS 요금이 남지 않게 |
| `~/.bus-step3/ssh_config` 생성 · 기동할 때마다 갱신 | 공인 IP가 바뀌어도 `ssh cp` |
| 기동할 때 보안 그룹의 내 IP 규칙 갱신 | 장소가 바뀌어 공인 IP가 달라져도 접속 |
| 삭제는 `delete` 입력 + 남은 자원 수 출력 | 실수 방지, 요금이 남지 않았는지 확인 |
| 이름 · 태그 bus-step3, 키는 `~/.bus-step3/` | 다른 실습 자원과 섞이지 않게, 비밀값은 레포 밖 |

노드끼리 모든 프로토콜을 여는 것은 수업과 같다. 3.4의 Calico IP-in-IP는 TCP · UDP가 아니라 IP 프로토콜 4라서 "모든 TCP"로는 Pod 통신이 안 된다. 6443(apiserver)은 밖에 열지 않는다 — kubectl은 cp에 SSH로 들어가 쓴다.

## 3. 스크립트

| 파일 | 하는 일 |
|---|---|
| `infra/step3/ec2/lib.sh` | 공통 값(이름 · 태그 · IP) · 함수 |
| `create-cluster.sh` | VPC → IGW → 서브넷 → 라우팅 → 보안 그룹 → 키 → 인스턴스 3대 → ssh_config → 표 |
| `stop-cluster.sh` | worker 2대 → cp 정지 |
| `start-cluster.sh` | cp → worker 2대 기동, 내 IP 규칙 · ssh_config 갱신 |
| `delete-cluster.sh` | 만든 순서의 반대로 삭제, 남은 자원 수 출력 |

## 4. 확인 (Claude 작업 환경)

AWS에 접근할 수 없어 `bash -n` · shellcheck와 가짜 `aws` 명령으로 실행 흐름(호출 순서 · 인자 · ssh_config 생성 · 권한 600)만 확인했다. 실제 결과는 Runbook.
