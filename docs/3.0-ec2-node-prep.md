# step3.0 클라우드 VM 준비 · 노드 사전 준비

수업 자료(Kubernetes Core)의 스크립트를 그대로 써서 AWS EC2 3대를 만들고, 02장 01 「노드 사전 준비」 절차대로 3대를 kubeadm이 요구하는 상태로 만든다. 스크립트는 이 레포에 복사하지 않고 수업 자료 폴더(`~\k8s-core`)에서 실행한다.

## 1. EC2 3대 (수업 `k8s-core/aws`, Windows PowerShell)

| 순서 | 명령 | 하는 일 |
|---|---|---|
| ① | `.\create-cluster.ps1` | VPC 192.168.0.0/16 · 서브넷 192.168.56.0/24 · IGW · 라우팅 · 보안 그룹(노드끼리 전체, 내 IP에서 22 · NodePort) · 키 페어 `key-k8s-core`(`~\.ssh\key-k8s-core.pem`) · Rocky 9 t3.medium 30GB 3대(사설 IP .10 · .11 · .12, 호스트 이름 cp · worker1 · worker2) |
| ② | `.\stop-cluster.ps1` | worker → cp 정지 |
| ③ | `.\start-cluster.ps1` | 보안 그룹 내 IP 갱신 → cp → worker 기동, Windows hosts 파일에 `공인IP cp` 등 갱신 (관리자 승인) |
| ④ | `.\watch-cluster.ps1` | 1분마다 사설 · 공인 IP 표 (Ctrl+C) |
| 삭제 | `.\delete-cluster.ps1` | 태그 Organization=k8s-core · Project=cluster 자원을 만든 순서의 반대로 삭제 (3단계를 모두 마친 뒤) |

자원 이름 `k8s-core-cluster-*`, 태그 Name · Organization=k8s-core · Project=cluster.

## 2. 노드 사전 준비 (수업 02장 01)

| 순서 | 항목 | 내용 | 안 하면 |
|---|---|---|---|
| 1 | 패키지 갱신 | `dnf -y update` → 재부팅 | 보안 패치 누락, 의존성 충돌 |
| 2 | 노드 이름 | `/etc/hosts` 에 cp · worker1 · worker2 = 192.168.56.10 ~ .12 | 이름으로 다른 노드를 못 찾음 |
| 3 | 시간 동기화 | chronyd active · synchronized yes | 인증서 유효기간 검사 실패 |
| 4 | swap | 클라우드 VM에는 없음 → 확인만 | kubelet 시작 실패 |
| 5 | SELinux · firewalld | permissive (`/etc/selinux/config` 도), firewalld 없음 → 확인만 | 컨테이너 파일 접근 거부 · 포트 막힘 |
| 6 | 커널 파라미터 | `/etc/sysctl.d/k8s.conf` `net.ipv4.ip_forward = 1` | 노드를 거쳐 Pod로 가는 패킷이 안 감 |
| 7 | containerd | Docker 저장소 `containerd.io`, 기본 설정 재생성(CRI 켜기), `SystemdCgroup = true` | kubelet이 컨테이너를 못 띄움 · 자원 압박 시 불안정 |
| 8 | Kubernetes 패키지 | v1.36 저장소 + `exclude=`, `--disableexcludes=kubernetes` 로 kubelet · kubeadm · kubectl · cri-tools 1.36.5, `/etc/crictl.yaml` | OS 갱신 때 버전이 바뀜 |
| 9 | kubelet 노드 IP | `/etc/sysconfig/kubelet` `--node-ip=192.168.56.x`, `enable --now` → activating (설정 파일은 kubeadm init · join 이 만듦) | 노드 주소가 잘못 잡힐 수 있음 |
| 10 | worker 2대 | 1 ~ 9를 묶은 수업 `02/01/prepare-node.sh` 를 scp로 복사해 `sudo bash prepare-node.sh 192.168.56.11` (.12) | — |

cp는 1 ~ 9를 한 단계씩 직접, worker는 스크립트로 한다. 클라우드 VM은 스냅샷 단계(11)를 건너뛴다.

## 3. 이 레포에서 바뀐 것
