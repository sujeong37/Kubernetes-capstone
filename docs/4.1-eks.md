# step4.1 EKS 만들기 (Auto Mode)

| 실행 (WSL) | 하는 일 |
|---|---|
| `bash infra/step4/eks/install-tools.sh` | kubectl · eksctl 설치 (`~/.local/bin`) |
| `bash infra/step4/eks/create-cluster.sh` | 점검(이름 · VPC · EIP 한도) → `eksctl create cluster -f cluster.yaml` (약 15~20분) → context `bus-eks` → 상태 |
| `bash infra/step4/eks/node-test.sh` | 노드 0대에서 Pod 2개 → Auto Mode 가 노드를 만드는 시간 |
| `bash infra/step4/eks/status.sh` | 상태 · 노드 · 요금 붙는 자원 (읽기만) |

`cluster.yaml`: bus-eks · 서울 2a/2b · VPC 10.20.0.0/16 (3단계 192.168.0.0/16 과 겹치지 않음) · NAT 1개 · `autoModeConfig.enabled: true`.

## 왜 eksctl 인가
VPC · IAM 역할(클러스터 · 노드) · 클러스터 · access entry · kubeconfig 를 설정 파일 하나로 만들고, `eksctl delete cluster -f` 가 같은 스택을 거꾸로 지운다 (4.9). 콘솔로 만들면 VPC · 역할을 따로 만들고 지울 때 순서를 사람이 기억해야 한다.

## EKS 가 대신하는 일

| 영역 | 3단계 (직접) | EKS Auto Mode |
|---|---|---|
| Control Plane | kubeadm init · 인증서 · etcd (3.1) | AWS 운영, 버전만 고름 |
| 노드 | EC2 3대 · kubeadm join · CSR 승인 (3.0 · 3.2) | Pod 요청에 맞춰 생성 · 교체 · 정리 |
| Pod 네트워크 | Calico IPIP · MTU · SG 프로토콜 4 (3.3) | VPC CNI 내장 — Pod 가 VPC 주소 |
| DNS · kube-proxy | Pod 로 설치 · 운영 | 내장 |
| 스토리지 | local-path 설치 (3.4) | EBS CSI 내장, StorageClass 만 직접 (4.2) |
| 입구 | Envoy Gateway + NodePort (3.6 · 3.8) | ALB 컨트롤러 내장 (4.2 · 4.3) |
| kubectl | ssh cp 후 | WSL 에서 IAM 인증 |
| 켜고 끄기 | stop · start | 정지 없음 → 끝나면 삭제 |

계정 ID 는 스크립트가 `****1234` 로 가린다 (eksctl 출력 포함).
